# Rulmera Radar 기술 기준선

기준일: 2026-09-16

## 1. 확정된 프로젝트 기준
- Rulmera Radar는 **Rulmera 자체 프로젝트**
- Rulmera 전체 개발 책임: **윤석훈**
- 레이더 모듈 제작사: **인지니어스**
- 인지니어스 오너/대표: **송문빈 대표**
- 모든 레이더 샘플과 기본 기술자료 공급 창구: **송문빈 대표**
- 이해관계자는 계속 추가 가능

## 2. 현재 제품 기준
- Radar Module: **AS_613 ×4 / 천장형 Radar Node 1개 기준**
- Radar MMIC: **Infineon XENSIV™ BGT60TR13C — 확인**
- 샘플 수량: **4개 공급 예정 — 확인**
- 상대 방위각: **약 90도 간격 후보**
- 하향각: **약 45도 후보**
- 실제 설치각: 실측 후 Freeze
- 큰 공간: Radar Node 추가
- 목표: 360도 감지 / Multi Radar Fusion / Tracking / Room Mapping / 자동 Wall Mask / Ghost·Noise 제거 / AI 보정
- PC 개발/학습: RTX 3060 또는 A6000
- Edge: Hub MCU 경량 추론
- Hub PCB/MCU: 신규 설계
- PSoC Edge E84: 후보, 미확정

## 3. BGT60TR13C 확정 사양
공식 Infineon 자료 기준으로 다음을 기술 기준선으로 사용한다.

- 60 GHz FMCW Radar
- RF 동작 범위: 약 **58.0 ~ 63.5 GHz**
- **1 Tx / 3 Rx**
- Antennas-in-Package(AIP), L자 배열
- 3개 Rx IF 채널에 대해 **12-bit ADC**, 최대 약 **4 MSps**
- 내부 FSM, FIFO, SPI 기반 설정/데이터 인터페이스
- Raw radar data는 Rx별 **Real IF sample**이며 직접 I/Q pair를 내보내는 구조가 아님
- FFT 이후 각 Range bin의 complex spectrum/phase를 계산하여 거리·속도·각도 처리에 사용 가능
- 공식 RDK/SDK에서 Raw frame 및 Range/Velocity/Angle 계열 개발 경로 확인

## 4. Infineon 공식 소프트웨어 기준
2026-09-16 조사 기준으로 실무 기준선은 아래와 같이 둔다.

- Radar Development Kit: **RDK 3.6.5 계열**
- 포함 Radar SDK: **3.6.4 계열**
- Python: `ifxradarsdk` / FMCW `DeviceFmcw` 계열
- C/C++: FMCW/Avian Device API 및 Raw frame API
- Radar Fusion GUI: 센서 설정, 시각화, 기록, MCU7 펌웨어 플래시 등 평가용
- BGT60TR13C 예제군: Raw data, Range, Range-Doppler, Range-Angle/Beamforming, Presence 등

> 공급받는 AS_613 전용 SDK/Library가 Infineon RDK를 그대로 노출하는지, 일부를 감싼 Wrapper인지, 완전히 별도 Proprietary Library인지는 아직 미확정이다.

## 5. 데이터 레벨 기술 기준
### L0 — Raw ADC / Real IF
형태 예:
```text
[Rx=3][Chirp][Sample]
```
주요 활용:
- Range FFT
- Rx별 amplitude/phase 분석
- Static clutter 추정
- Micro-motion 특징
- 자체 DSP 검증

### L1 — DSP Intermediate
- Range Spectrum
- Range-Doppler Map
- Range-Angle / Beam Map
- Capon/DBF Angle response
- Detection point / Peak list
- SNR/Power/Noise floor

주요 활용:
- Ghost 분류
- 객체 분리
- Association 보조
- 벽/반사 패턴 학습

### L2 — AS_613 Target-level
- x/y/z
- velocity
- size/extent
- confidence/SNR/quality
- vendor target id
- status/flags

주요 활용:
- Multi Radar Fusion
- Tracking
- Room Mask
- Ghost probability
- Merge/Split 보정

## 6. AS_613 매뉴얼 기반 확인사항
- 60 GHz FMCW 통합 레이더 솔루션
- GPIO/UART/USB 인터페이스
- Wall/Ceiling 설치 모드
- 좌표/ROI/각도 설정
- Wall tilt 0~45° 보정
- `op` 설정이 Signal Processing Grid/Capon Map 축 선택과 연결
- 최대 약 5 Target, 통상 약 10 Hz 수준의 처리된 Target 출력 기술
- 반사 Phantom, 이동 물체 False Detection, 근접 인원 Merge, 정지 Target 흔들림 가능

## 7. 현재 가장 중요한 기술 해석
기존에는 정확한 MMIC 자체가 미확정이었으나 현재 **BGT60TR13C로 확정**되었다.

따라서 이제 질문은 “칩이 Raw 데이터를 만들 수 있느냐”가 아니라 **“AS_613 펌웨어/라이브러리가 어느 Data Level까지 외부에 노출하느냐”**로 바뀐다.

### 확정
- BGT60TR13C는 3Rx Real IF Raw ADC를 생성 가능
- Infineon 공식 RDK는 DEMO 개발 환경에서 Raw frame을 PC에 전달 가능
- Range/Doppler/Angle 계열 알고리즘/예제가 제공됨
- BGT60TR13C 자체는 직접 I/Q pair 출력 방식이 아님

### AS_613에서 미확정
- 공급 SDK/Library 정확한 이름/버전
- Raw ADC export API
- Range-Doppler export API
- Detection Point export API
- Range-Angle / Capon Grid export API
- SNR/Confidence 필드
- Radar 내부 Timestamp/Frame counter 노출
- HW Trigger/Sync
- 4개 동시 운용 시 간섭 회피 기능
- AS_613 Host MCU/Bootloader 종류
- AS_613 펌웨어 업데이트/복구/롤백 절차

## 8. 펌웨어 경계
```text
[BGT60TR13C MMIC]
  - FMCW/RF/ADC/FIFO/FSM/SPI
        │
        ▼
[AS_613 Host MCU + 인지니어스 Firmware]
  - Sensor register 설정
  - Raw 수집 여부
  - Vendor signal processing
  - Target protocol
  - USB/UART/GPIO
        │
        ▼
[Rulmera Adapter / PC Reference Engine]
```

Infineon DEMO-BGT60TR13C의 Radar Baseboard MCU7 펌웨어는 **참고 구현**이다. 실제 AS_613가 MCU7이 아닌 이상 MCU7 펌웨어 바이너리를 AS_613 업데이트에 사용하지 않는다.

## 9. 소프트웨어 계층 기준

```text
[AS_613 #1..#4 / BGT60TR13C]
    │  Vendor protocol / SDK
    ▼
[Radar Adapter ×4]
    │  Common Radar Frame
    ▼
[Raw/Intermediate Logger] ── optional by API exposure
    │
    ▼
[Time Alignment]
    ▼
[Coordinate Transform / Calibration]
    ▼
[Candidate Association]
    ▼
[Multi Radar Fusion]
    ▼
[Tracking]
    ▼
[Room Model / Wall Mask]
    ▼
[Ghost & Noise Suppression]
    ▼
[AI Correction]
    ▼
[Application Output / Event]
```

## 10. PC→Edge 원칙
- PC Reference Engine이 기능 정본
- 모든 알고리즘은 저장 로그 Replay 가능
- Edge는 같은 Common Data Contract를 사용
- MCU 선정은 프로파일링 후
- AI는 경량 모델 또는 Rule+ML 혼합으로 이관
