# 프로젝트관리계획

## 수행 방식과 생명주기
**점진적 검증형(Iterative / Evidence-driven)** 으로 수행한다. 제조사 인터페이스가 아직 Freeze되지 않았으므로, 문서상 추정과 실제 샘플 검증을 분리한다.

1. 자료/샘플 확인
2. 단일 Radar Bring-up
3. Multi Radar Logger
4. Calibration / Time Alignment
5. Fusion / Tracking
6. Mapping / Mask / Ghost Filter
7. AI 보정
8. Edge 이관
9. 현장 검증

## 단계·승인 게이트

| 단계 | 시작조건 | 완료조건 | 승인 |
|---|---|---|---|
| G0 착수 | 프로젝트 정의 | 역할·기준선 등록 | 윤석훈 |
| G1 Vendor Freeze | 샘플/자료 확보 | MMIC·SDK·출력레벨 확인 | 윤석훈 |
| G2 Data Freeze | Logger 동작 | 4 Radar 공통 로그 확보 | 윤석훈 |
| G3 Geometry Freeze | 설치 Jig | 좌표/각도 Calibration 완료 | 윤석훈 |
| G4 Fusion MVP | 동기화 로그 | Tracking 데모 | 윤석훈 |
| G5 Robustness | Room 시험 | Wall/Ghost 억제 검증 | 윤석훈 |
| G6 AI | 라벨/Replay | A/B 개선 증빙 | 윤석훈 |
| G7 Edge | MCU 선정 | PC-Edge 결과 비교 통과 | 윤석훈 |

## 범위·일정·비용 기준선
범위는 `07-범위-WBS.md`, 기술 기준은 `20-기술-기준선.md`를 정본으로 한다. 일정은 OpenProject 연결 후 작업패키지로 운영한다.

## 요구사항·변경 통제
- 확인 사실 → 기준선 반영
- 미확인 가설 → `05-가정-제약조건로그.md` 또는 `90-근거-기록/03-기술가설-검증로그.md`
- 제조사 답변으로 기존 가정이 깨지면 변경로그와 기술 기준선 동시 수정

## 품질·검증·인수 방식
모든 핵심 알고리즘은 **Recorded Replay**로 동일 입력을 반복 재현할 수 있어야 한다. PC Reference 결과를 기준으로 Edge 결과를 비교한다.

## 위험·이슈 관리 방식
- 개발을 막는 사실 미확정: Issue
- 발생 가능 미래 사건: Risk
- 즉시 실행할 확인 작업: Action Item

## 의사소통·보고 주기
- 송문빈 대표/인지니어스: 샘플, FW, SDK, API, MMIC, 동기화/출력 관련 필요시 질의
- Rulmera 내부: 기술 기준선 변경 즉시 기록

## 형상·버전·문서 관리
