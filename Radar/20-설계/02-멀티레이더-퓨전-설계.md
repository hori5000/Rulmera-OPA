# Multi Radar Fusion 설계

## 왜 단순 좌표 평균이 아닌가
레이더마다 관측 시각, 오차, 사각, 반사, Target merge가 다르므로 같은 프레임 번호끼리 좌표를 평균하면 오히려 결과가 나빠질 수 있다.

## 처리 순서
1. 각 센서 Frame을 공통 시간축으로 정렬
2. Local 좌표를 Room 좌표계로 변환
3. 기존 Track을 현재 시점으로 예측
4. Sensor Observation과 기존 Track 간 후보 Gate 생성
5. 거리/속도/방향/신뢰도 기준 Association
6. 동일 객체로 판단된 관측을 가중 Fusion
7. 관측되지 않은 Track은 일정 시간 예측 유지
8. 신규 관측은 N회 연속 확인 후 Track 승격
9. 짧고 낮은 신뢰도의 관측은 Noise 후보로 제거

## Track 상태 예시
```text
track_id
position_room[x,y,z]
velocity_room[vx,vy,vz]
confidence
age
last_update
source_sensors[]
support_count
ghost_score
wall_score
ai_score
```

## Association 기본 점수
```text
score =
  w1 * position_distance
+ w2 * velocity_difference
+ w3 * direction_difference
- w4 * confidence
+ w5 * wall_penalty
```

초기에는 규칙 기반으로 시작하고, 실제 로그가 쌓이면 Association/Confidence 보정을 학습시킬 수 있다.

## 중요한 원칙
- Vendor Target ID를 전역 ID로 믿지 않는다.
- 센서가 다르면 같은 사람도 다른 ID로 나올 수 있다.
- Track은 Rulmera가 새로 만든다.
- 센서가 1개 잠시 놓쳐도 다른 센서가 Track을 이어갈 수 있어야 한다.
