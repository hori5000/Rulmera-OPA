# 중랑 M203 데이터수집팀 작업지시서

> **데이터 수집 담당자는 우선 이 문서만 기준으로 작업을 시작한다.**  
> 현재 범위는 **중랑 M203 송풍기**다. M204/M102는 별도 작업지시가 나오기 전까지 확대하지 않는다.

## 1. 이번에 수집팀이 해야 하는 일

AI 모델을 만들라는 작업이 아니다. 아래 항목을 **현장/PLC/SCADA/Logger/DB에서 직접 확인하고 결과를 채워서 전달**하는 작업이다.

| 확인항목 | 해야 할 일 | 완료 기준 |
|---|---|---|
| PLC Symbol/주소 | M203 관련 Symbol과 실제 주소 재확인 | Symbol·주소가 매핑표와 일치 |
| SCADA Tag | PLC 신호가 CIMON에서 어떤 Tag로 사용되는지 확인 | PLC↔SCADA Tag 연결 확인 |
| Logger 저장 | AI/DI Logger에 해당 Tag가 실제 저장되는지 확인 | Logger명·주기·기간 확인 |
| DB/SQL 저장 | 필요한 경우 운영 DB/SQL에 같은 신호가 남는지 확인 | Table/Column/Tag/시간축 확인 |
| 단위/범위 | DO, Hz, 유량, 전력 등 단위와 정상 범위 확인 | 단위·Min/Max 또는 관측범위 기입 |
| Mode/상태 | AUTO/MANUAL, RUN, Fault, Interlock, 선택 Mode 저장 여부 확인 | 저장 위치 또는 미수집으로 표시 |
| Set Point | DO Set, Mode별 Hz, Timer 등 이력 저장 여부 확인 | Logger/SQL/미수집 구분 |
| 품질 | 결측·고정값·통신중단·중복 확인 | 기간/결측률/이상구간 요약 |

## 2. 가장 먼저 볼 기준 문서

1. **M203 PLC-SCADA-Logger Mapping**

   - 이 표의 미확인/빈 항목을 수집팀이 확인해서 채운다.
2. [[05-M203-Master-Dataset-정의|M203 Master Dataset 정의]]  
   - AI에서 최종적으로 어떤 컬럼이 필요한지 확인한다.
3. [[../20-현장-시스템/07-A2-PILOT-PLC-Rule-Book|M203 송풍기 PLC Rule Book]]  
   - 각 값이 PLC에서 어떤 의미로 쓰이는지 확인한다.
4. [[../20-현장-시스템/08-M203-PLC-Cause-Tree|M203 PLC Cause Tree]]  
   - DO·Mode·Fault·Interlock·Hz 관계를 이해한다.
5. [[03-장기-SCADA-Logger-데이터-확보현황|장기 SCADA Logger 확보현황]]  
   - 이미 확보된 것과 추가 확인할 것을 구분한다.

## 3. 질문하기 전에 확인할 순서

```text
① Mapping 표 확인
   ↓
② PLC/XG5000 Symbol·주소 확인
   ↓
③ CIMON Tag/Logger 설정 확인
   ↓
④ 실제 CLD/CSV 또는 SQL 이력 확인
   ↓
⑤ 결과를 Mapping 표에 기록
   ↓
⑥ 그래도 판단이 안 되는 항목만 질문
```

단순히 “태그가 뭐냐”, “DB에 있냐”, “어디서 받냐”를 질문으로 넘기지 않는다. **위 자료에서 먼저 확인한 뒤, 확인한 근거와 함께 미확정 항목만 올린다.**

## 4. 현재 M203에서 우선 확인할 신호

| 그룹 | 우선 신호 | 기준 |
|---|---|---|
| 공정 | DO, MLSS, 유입/공정유량, 송풍량 | AI Logger 및 PLC 주소 확인 |
| 설비 | M203A/B RUN, Fault | DI Logger 확인 |
| 제어 | AUTO/MANUAL | Logger/SQL 저장 여부 확인 |
| 제어 | 선택 DO Mode | `PID.M_203A.AI_DO_MOD_SET` 계통 |
| 제어 | Mode별 Hz / 수동 Hz / 최저 Hz | PLC Rule + SCADA/이력 확인 |
| 제어 | Timer ON/OFF 설정·진행값 | PLC/SCADA/Logger/SQL 확인 |
| 안전 | Interlock / Run Permit 계통 | PLC Rule 상세식과 이력 여부 확인 |
| 결과 | 실제 Hz | `PID.M_203A.AI_HZ_IN` 계통 |
| 에너지 | M203 유효전력, kWh, PF, 전류 | `AI.E_M_203.*` 계통 |

## 5. 수집팀이 넘겨야 하는 결과물

최소 제출물은 다음 3개다.

- 업데이트된 `04-M203-PLC-SCADA-Logger-Mapping.csv`
- `M203_수집확인결과.md` 또는 동등한 확인기록
- 실제 확인 근거: 설정 화면/파일명/Tag/SQL/Logger 경로/샘플 데이터

`확인`, `미확인`, `해당없음`, `추가확인필요`를 구분해서 적는다. 추정으로 빈칸을 채우지 않는다.

## 6. 역할 경계

- **데이터 수집 담당**: PLC/SCADA/Logger/DB에서 실제 신호·주소·Tag·주기·이력·품질을 확인하고 매핑표를 완성한다.
- **AI 담당**: 확인된 데이터를 동일 시간축으로 정리하고 Master Dataset, 특징량, 예측·전력·최적화 모델을 만든다.
- **하드웨어/임베디드 담당**: 현장 통신·인터페이스·안전조건 확인에 협업한다.
- **PM**: 우선순위·대외확인·수용을 조정한다.

## 7. 현재 AI 쪽에서 이미 완료한 기준선

- M203 PLC Cause Tree 작성
- M203 Rule Book v1.0 작성
- M203 PLC↔SCADA↔Logger Mapping 기준표 작성
- M203 Master Dataset 컬럼 정의
- 장기 SCADA Logger 확보·샘플링·검증 상태 정리

따라서 수집팀은 **새로 무엇을 수집할지 다시 정의하는 것이 아니라, 위 기준선의 실제 현장/이력 존재 여부를 확인하고 빈칸을 닫는 작업**부터 진행한다.
