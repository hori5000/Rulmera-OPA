# 중랑 DB 구조와 시간축 해석

## 현재 확인된 내용

### `suyo.tb_suyo`

현재 분석자료 기준 물리 컬럼은 다음 5개다.

| 컬럼 | 의미 |
|---|---|
| Num | PK / 순번 |
| TAGNAME | SCADA Tag 이름 |
| DESCRIPT | 설명 |
| PV | 값 |
| DATETIME1 | DB 입력시각 성격의 timestamp |

즉 **226개 신호가 226개 컬럼으로 저장되는 구조가 아니라, 5개 컬럼의 Long 구조에 TAGNAME별 행이 반복 저장**되는 형태다.

### SCADA SQL 설정과 실제 운영 DB가 달라 보이는 이유

| 구분 | 물리 필드 수 | Tag/변수 수 | 해석 |
|---|---:|---:|---|
| 실제 `suyo.tb_suyo` | 5 | 226 Active | Long Tag History |
| `ELECTRIC_DATA` 설정 | 101 | 전력 100 | SCADA Wide SQL 설정 |
| `OPERATOR_DATA` 설정 | 207 | 공정 206 | SCADA Wide SQL 설정 |
| `SURVEY_DATA` 설정 | 5 | 수질 4 | SCADA Wide SQL 설정 |
| `TMS_DATA` 설정 | 5 | 유량/송풍 4 | SCADA Wide SQL 설정 |
| `water_input` 설정 | 16 | 수질 14 | SCADA Wide SQL 설정 |

`설정이 존재한다`와 `현재 운영 DB에서 실제 테이블로 사용된다`는 같은 의미가 아니다.

## 시간차 원인

분석자료에서는 `DATETIME1 = current_timestamp()` 성격으로 정리되어 있으며 226개 Tag가 순차 INSERT되면서 한 Cycle이 초 경계를 넘는 현상이 관찰되었다.

| 관찰 | 실측 예 | AI 처리 방향 |
|---|---|---|
| 같은 Cycle이 두 초에 걸쳐 저장 | `16:37:32 = 66개`, `16:37:33 = 160개` | Timestamp만으로 Cycle 묶지 않음 |
| Tag 순서 반복 | 최근 완성 Cycle간 `MISMATCH_COUNT=0` | Num/Tag 순서를 복원 보조키로 활용 |
| DB 입력시각 성격 | `DEFAULT current_timestamp()` | `sample_time`과 `received_at` 분리 |

## 확보된 장기 Logger와 운영 SQL/DB의 구분

- AI 학습에 사용할 장기 운전이력은 **CIMON SCADA Logger(CLD/CSV)로 이미 확보**되어 있다. 기간은 2025-09-24~2026-08-05이며 샘플링과 CLD↔CSV 대조도 수행했다. 상세는 [[03-장기-SCADA-Logger-데이터-확보현황]]을 참조한다.
- 아래 `junglang` 오류는 **운영 SQL/DB 연계 경로의 상태 문제**이며, 기존 장기 Logger 데이터가 없다는 뜻이 아니다.

## 2026-09-07 PC 수집본에서 추가 확인된 운영 SQL/DB 위험

- `HMI/Log`의 2026-07-09~09-07 XLOG 61개 모두에서 `junglang 데이터베이스의 연결 실패`가 확인되었다.
- 오류 문구는 ODBC 데이터 원본/기본 드라이버 문제를 가리킨다.
- 따라서 기존 `suyo.tb_suyo` 구조 분석은 **확보된 DB 자료의 구조 해석**으로는 유효하지만, **이번 HMI PC가 해당 기간 실제 운영 DB에 정상 적재했다고 가정해서는 안 된다.**
- `junglang` DSN이 어느 운영 DB를 가리키는지, 별도 서버가 있는지, 현재 실시간 적재가 정상인지 확인해야 한다. 이 확인은 **실시간 AI 연계 설계**를 위한 것이다.
- XLOG는 CIMON Runtime 진단로그로 분류하며 AI 학습 Raw History로 사용하지 않는다.

문제해결 추적: [[../60-문제해결/01-CIMON-junglang-SQL-연결실패]]

## AI Master DB 제안

Raw 수집 단계:

- `cycle_id`
- `sample_time`
- `received_at`
- `plant_id`
- `source_id`
- `tag_id`
- `value_raw`
- `value_eng`
- `quality`

학습/분석 단계에서는 동일 시간축으로 Pivot한 Wide 구조를 별도 생성한다.

## 추가 확인 필요

- SCADA Script가 별도의 측정시각을 명시적으로 넘기는지 최종 확인
- 운영 SQL/DB 서버 위치, `junglang` ODBC DSN, DBMS, 현재 적재 테이블 및 실시간 부하 조건
- 실시간 연계 시 저장주기·장애복구·Buffer/재전송 정책
