# 중랑 원천 DB 적용 가이드

## 1. 현재 확인된 Source 성격

중랑은 **한 종류 DB가 모든 데이터를 저장하는 구조가 아니다.** SCADA Logger 장기이력과 SQL 설정/운영 DB가 함께 존재한다.

| Source | 현재 확인된 구조/이름 | 성격 | 처리 원칙 |
|---|---|---|---|
| `suyo.tb_suyo` | `Num`, `TAGNAME`, `DESCRIPT`, `PV`, `DATETIME1` | Long Tag History | 원본명/Tag를 보존하고 Canonical Signal FK로 연결 |
| `ELECTRIC_DATA` 설정 | 약 101 field | SCADA Wide SQL 설정 | 실제 운영테이블 여부를 먼저 확인하고 Source Object로 등록 |
| `OPERATOR_DATA` 설정 | 약 207 field | 공정 Wide SQL 설정 | 동일 |
| `SURVEY_DATA` 설정 | 5 field | 수질 관련 설정 | 동일 |
| `TMS_DATA` 설정 | 5 field | 유량/송풍 관련 설정 | 동일 |
| `water_input` 설정 | 16 field | 수질 관련 설정 | 동일 |
| CIMON AI Logger | 장기 CLD/CSV | 약 15초 시계열 | 장기 AI/분석 원천으로 활용 |
| CIMON DI Logger | 장기 CLD/CSV | 약 15초 상태값 | RUN/Fault/Mode 계열 원천 |
| CIMON DI2 Logger | CLD/CSV | 약 1초, M301 관련 | 별도 Source로 관리 |

## 3. 중랑 권고 설계

**A안 권고.** `tb_suyo`나 CIMON Logger 형식을 공통 DB의 최종 Schema로 그대로 쓰지 않는다.

```text
원본
 ├─ suyo.tb_suyo
 ├─ CIMON AI/DI/DI2 Logger
 └─ SCADA Wide SQL 설정/운영테이블
        ↓
waterai_jungnang.raw
        ↓
meta.signal_mapping
        ↓
waterai_jungnang.core.timeseries / control_state / event
        ↓
기관공유 View + AI Dataset Mart
```

### 핵심 Mapping 필드

```text
source_database
source_table_or_logger
source_tag
plc_symbol
plc_address
scada_tag
signal_id
equipment_id
unit
sample_cycle
quality_rule
```

### Timestamp

`tb_suyo.DATETIME1`은 DB 입력시각 성격이므로 Canonical DB에서는 최소 다음을 분리한다.

```text
source_time
sample_time
received_at
cycle_id
```

## 4. 중랑에서 B안을 선택할 수 있는 경우

- 전체 일정상 A안 Metadata/Canonical 구조를 즉시 구축할 시간이 없는 경우
- 우선 `tb_suyo`/Logger를 Replica하고 View로 기관 공유를 먼저 열어야 하는 경우

단, B안을 써도 `signal_mapping`과 `dataset_manifest`는 반드시 만든다.

## 5. 중랑 구축 완료 기준

- `tb_suyo`/Logger/SCADA Source가 한 개의 Source Registry에서 조회됨
- M203 대표기간에 대해 원본→Core 값 검산 성공
- `TAGNAME/PLC주소/SCADA Tag/Canonical ID` 역추적 가능
- AI/DI 시간축 결합 규칙 문서화
- 대학/에이치코비가 읽기전용 View로 같은 데이터를 조회 가능
- 4인 검토 Gate 완료
