# 명장 원천 DB 적용 가이드

## 1. 현재 확인된 수준

명장은 정수 AI 기술의 **최종 적용/실증 대상**으로 관리한다. 현재 Obsidian에 축적된 세부 PLC/HMI/Historian/DB 분석은 광암이 훨씬 앞서 있으며, 명장의 실제 Database/Table/Tag 구조는 아직 동일 수준으로 확보되지 않았다.

따라서 **광암 DB명을 명장에 그대로 적용하거나 광암 Schema를 현장 원본이라고 가정하면 안 된다.**

## 2. 개발 원칙

```text
광암 원천 DB/운전데이터 분석
→ 정수 Canonical Schema/Feature 표준화
→ 명장 Source Inventory
→ Feature Compatibility 비교
→ 명장 원천 DB 구축/Mapping
→ 필요 시 재학습·보정·현장 파라미터 조정
```

## 3. 명장 착수 전 필수 Source Inventory

| 구분 | 확인 항목 |
|---|---|
| PLC | 제조사/CPU/네트워크/주소체계 |
| HMI/SCADA | 제품, Tag Export, Logger/Historian |
| DB | 제품, Database/Schema/Table/Column, 보존기간 |
| 정수 공정 | 원수/정수량, 탁도, 수질, 약품 PV/SV, 펌프, 전력 |
| 제어 | AUTO/MANUAL, RUN, Alarm/Fault, Set Point |
| 품질 | Timestamp, 저장주기, 결측, Quality Code |

## 4. 설계 선택

- 명장 Source가 광암 Historian과 구조적으로 유사하고 장기값/Metadata가 분리돼 있으면 **A안 권고**
- 일정상 먼저 운영 DB Replica를 열어야 하면 **B안으로 시작 후 A안 전환**

어느 경우든 `plant_id`, `signal_id`, `equipment_id`와 Source Mapping을 사용해 **광암과 명장의 물리 Tag명이 달라도 같은 Canonical Feature로 비교**할 수 있어야 한다.

## 5. 완료 기준

- 명장 실제 Database/Table/Tag 목록 확보
- 광암↔명장 Feature Compatibility 작성
- 정수 공통 Canonical Signal과 명장 Source Mapping 완료
- 대표기간 적재/조회/품질 시험
- 외부기관 읽기전용 View 제공
- 4인 검토 Gate 완료
