# 광암 원천 DB 적용 가이드

## 1. 현재 확인된 Source 성격

광암은 **Alarm/Event DB와 Historian 공정 시계열을 반드시 분리**해야 한다.

| Source | 확인된 객체/이름 | 성격 | 처리 원칙 |
|---|---|---|---|
| `WWALMDB` | Alarm DB Logger 계열 | Alarm/Event SQL 이력 | `raw.event`로 적재, 공정 PV와 혼합 금지 |
| `Runtime` | `Tag`, `AnalogTag`, `DiscreteTag`, `StringTag` | Historian Tag/설정 메타 | `meta.signal`/`meta.signal_mapping`의 근거 |
| `Runtime` | `IOServer`, `Topic` | 수집 Source 메타 | `meta.source_system` 근거 |
| `Runtime` | `StorageNode`, `StorageLocation` | History Storage 위치/정책 | Source Registry/보존정책 근거 |
| `Runtime.dbo.History` | SQL 조회 인터페이스 | 실제 Historian 시계열 조회 | 장기 Export 후 `raw.timeseries` 적재 |
| History Storage | Circular/Overflow/Buffer/Permanent | 실제 장기 값 저장계층 | 원본 인수 또는 Export 대상 |
| InTouch DBDump / `dde.cfg` | TagName/Topic/Item(MW주소) | HMI Tag↔PLC 통신 주소 | Canonical Mapping 근거 |

## 3. 광암 권고 설계

**A안 강력 권고.** `Runtime`과 `WWALMDB`를 새 원천 DB의 한 테이블로 합치지 않는다.

```text
PLC/GFENet
   ↓
InTouch / Historian
   ├─ Runtime 메타 + History 조회
   └─ WWALMDB Alarm/Event
        ↓
waterai_gwangam.raw.timeseries
waterai_gwangam.raw.event
        ↓
meta.signal + meta.signal_mapping
        ↓
core.timeseries + core.event + core.control_state
        ↓
기관공유 View / 정수 AI Dataset
```

### 광암 Canonical Mapping 핵심

```text
Historian TagName
Description
IOServer
Topic
ItemName(MW주소)
StorageRate
Source PLC/Topic
Canonical signal_id
Canonical equipment_id
Unit
Quality
```

### Alarm 결합

`WWALMDB`는 Event 원천으로 유지하고, 공정값과의 결합은 **Timestamp + Signal/Equipment Mapping**을 통해 조회/분석 단계에서 수행한다.

## 4. 현재 가장 중요한 미확보 항목

- 장기간 `History` Export 또는 History Storage 원본
- 최초/최종 DateTime
- AI 대상 Tag의 Quality/보존주기
- 현재 운영 Tag와 Runtime Tag의 최신성 검증

장기 값이 확보되기 전에도 Meta/Mapping Schema는 먼저 구축할 수 있다.

## 5. 광암 구축 완료 기준

- `Runtime Tag ↔ DDE Item(MW) ↔ PLC ↔ Canonical signal_id` 추적 가능
- `WWALMDB` Event와 Historian PV가 별도 Raw Table로 적재됨
- 대표 Tag `History` Export 적재/검산 성공
- 약품 PV/SV, 수질, 유량, 펌프 Hz/RUN, 전력, Alarm을 기관 View에서 조회 가능
- 광암 데이터 기반 정수 AI Dataset Manifest 생성 가능
- 4인 검토 Gate 완료
