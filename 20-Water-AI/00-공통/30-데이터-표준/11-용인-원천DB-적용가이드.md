# 용인 원천 DB 적용 가이드

## 1. 현재 확인된 수준

현재 자료에서는 용인 실증 대상과 데이터 인프라/센서 구성 방향은 확인되지만, **중랑처럼 실제 운영 DB의 Database/Schema/Table/Column 원본까지 분석된 상태는 아니다.**

따라서 중랑의 테이블명을 복사해서 용인 DB를 설계하면 안 된다.

### 현재 자료로 확인 가능한 방향

- 하수 공정 운영·수질·제어·전력 Time-Series 확보가 목적
- 센서/분석기, 설비 상태, 유량·전력 데이터가 AI·DT 입력이 됨
- 고주기 데이터 수집/중앙 저장 인프라가 계획·구축 범위에 포함

## 2. 용인 착수 전 필수 Source Inventory

코이넷 수집 담당이 아래를 먼저 채운다.

| 구분 | 확인 항목 |
|---|---|
| DB | 제품, 서버, Database명, Schema명, Table명, PK/Index |
| HMI/SCADA | 제품명, Tag DB, Logger/Historian 종류 |
| PLC/ECP | 장비명, 주소체계, 수집프로토콜 |
| 시계열 | Timestamp 필드, 저장주기, Quality, 보존기간 |
| 제어 | RUN/AUTO/MANUAL/Set Point/Fault/Interlock 저장여부 |
| 전력 | 설비별 kW/kWh/전류/PF/운전 Hz 연결여부 |

## 3. 설계 선택

- 실제 DB가 하나의 안정된 Time-Series Schema로 이미 구축돼 있고 외부 참조만 필요하면 **B안으로 빠르게 Replica+View** 가능
- Source가 PLC/ECP/HMI/여러 테이블로 분산돼 있거나 장기 확장이 필요하면 **A안 권고**

## 4. 용인 DB 설계 전 금지사항

- 중랑의 `tb_suyo` 구조를 용인에 그대로 적용
- 용인 실제 Source 조사 없이 `TAGNAME/PV/DATETIME1` 컬럼을 가정
- 대학/외부기관에 운영 DB 직접 쓰기권한 제공

## 5. 완료 기준

1. Source Inventory 완료
2. 실제 DB/Table/Column 목록 첨부
3. A/B안 선택 및 사유 기록
4. 대표 1일 데이터 적재시험
5. Canonical Mapping 작성
6. 4인 검토 Gate 완료
