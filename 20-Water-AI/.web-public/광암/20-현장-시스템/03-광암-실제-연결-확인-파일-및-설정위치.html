광암 PLC → DeviceXPlorer → InTouch → Historian/DB 실제 연결 확인 위치

0. 목적

현재 확보한 Wonderware.zip으로 제품 구성과 PLC 통신 대상은 상당 부분 확인했지만, 광암에서 런타임 데이터가 실제로 어느 경로로 흐르는지는 운영 설정을 대조해야 최종 확정할 수 있다.

XG5000 원본이 확보되었으므로 이제 아래 5개 연결을 각각 증명해야 한다.

그리고 InTouch 자체의 .LGH/.IDX Historical Logging이 별도로 사용 중인지도 함께 확인한다.

1. A0구간 — 현장 신호 → PLC 주소/프로그램/PLC간 전송

XG5000 .xgwx 155개 수집본이 확보되어 이 구간은 이제 파일 기반 분석이 가능하다.

다만 155개에는 동일 PLC의 과거본/수정본/OLD가 포함되어 있으므로 우선 현장 PLC Canonical ID와 현재본 후보를 정규화한다.

확인할 항목:

특히 PCS2↔FCC 24개 구조는 송수신 Word 영역까지 추출하여 통신 Matrix로 만든다.

세부: 04-광암-PLC-XG5000-구조-및-통신맵

2026-09-09 수집 완료 상태

기존 체크리스트 중 다음은 더 이상 ‘미확보’가 아니다.

현재 1순위 미확정은 다음으로 다시 좁혀졌다.

  1. 2026 현재 Historian 실제 History Storage 원본 또는 장기간 Timestamp/Value/Quality Export 확보
  2. backup2.bak 최신 Runtime의 StorageLocation.Path 실제값 조회 및 Storage Node 확인
  3. 현재 GFENet Application의 실제 실행 프로세스/제품 정체
  4. GFENet ↔ DeviceXPlorer 관계
  5. XG5000 Online Compare로 현행 PLC 프로젝트 확정
  6. DDE Item(MW주소) ↔ XG5000 Symbol/Program Block JOIN

2026-09-09 DB 백업 분석 완료 반영

추가로 다음 BAK는 이제 “정체 미확정”이 아니다.

최신 Runtime에는 StorageLocation.Path 컬럼이 실제 존재한다. 다음 SQL 조회를 현장에서 직접 수행하면 현재 Storage 경로를 재확인할 수 있다.

이후 해당 Path의 실제 History Storage 파일을 확보하거나 Historian Query/Export로 장기 값을 추출한다.

2026-09-09 Historian 실제 저장파일 현장 확보 추가 확인

현장시간이 짧으므로 POS11에서 장기 SQL Export를 먼저 수행하기보다 실제 History Storage 위치와 크기를 빠르게 확인한다.

SQL로 저장위치 확인

StorageLocation.Path를 현재값의 1차 기준으로 사용한다. 2022 자료의 D:\Historian\Data\Circular / Buffer / Permanent는 비교 근거이지 2026 현재값 확정치로 사용하지 않는다.

PowerShell로 용량 확인

용량이 이동매체로 감당 가능하면 History Storage 원본 + 최신 Runtime BAK + StorageLocation/StorageNode 결과를 세트로 확보하는 방향을 우선 검토한다.

단, 운영 중 Storage의 단순 복사가 정합성 있는 백업을 보장하는지는 추가 확인이 필요하므로, 실제 복사 전에 현장 담당자에게 정식 Backup/Snapshot 방식 또는 운영 중 복제 가능 여부를 확인한다. Historian/SQL 서비스를 임의 중지하지 않는다.
