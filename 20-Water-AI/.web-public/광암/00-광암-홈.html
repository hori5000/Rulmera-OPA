현재 상태

  • 현장 확인: 2026-09-07 현장방문 완료
  • PLC 원본: XG5000 .xgwx 155개 수집 완료(오류 0). 단, 동일 설비의 과거본/수정본/OLD가 포함되어 있어 155개를 PLC 155대로 해석하지 않음
  • PLC 구조: PCS1/2/4/5/6, PCS_M, P22 약품, P23 오존, CO2, 염소 및 FCC 24개 여과지 로컬 PLC 계층 확인
  • PLC 통신: 주요 PCS에서 192.9.211.x / 192.9.212.x FEnet 계열의 복수 통신 경로 확인. Primary/Standby 의미는 추가 확인
  • PLC 과거이력: PLC 자체 장기 백업 없음
  • HMI: Wonderware InTouch HMI 2014 R2 SP1 (v11.1) 구성 확인
  • PLC 통신 미들웨어: TAKEBISHI DeviceXPlorer 5.4.0.1. 산업용 통신 미들웨어/OPC·SuiteLink Server이며 DXPSV.dxp에서 LsisEthernet 구성 확인
  • PLC 통신 대상: 광암 설비 13개 대상, 설정상 원격 IP 192.9.211.10~32 범위의 개별 주소와 TCP 2004 사용 확인
  • Historian: Wonderware Historian Server 2014 R2 SP1 (v11.6.13100) 구성 확인. historian.txt와 Runtime DB 백업으로 실제 Historian Tag/Storage 메타구조까지 확인
  • 알람 DB: 기존 분석한 WWALMDB는 InTouch Alarm DB Logger 계열의 알람·이벤트 SQL DB로 분류. Historian 공정 시계열 DB와 구분
  • 현재 HMI 통신 근거: 2026 dde.cfg에서 주요 PLC Source는 \\192.9.211.120\GFENet / SuiteLink로 확인. GFENet과 DeviceXPlorer의 실제 런타임 관계는 별도 확인 필요
  • FSGateway: 설치 구성요소 존재는 확인했으나 실제 런타임 통신 경로 사용 여부는 미확정
  • 학습 데이터 상태: 현장 POS11의 Runtime.dbo.History 조회에서 실제 TagName / DateTime / vValue / Quality 시계열 값이 반환되는 것이 사진으로 직접 확인됨. 다만 우리가 받은 Runtime/Holding/backup2 BAK에는 장기 값 본체가 포함되지 않았고, AI 학습용 장기간 Export/History Storage 원본은 아직 인수하지 못함
  • 다음 작업 1순위(데이터 확보): 현장 체류시간이 짧으므로 POS11에서 먼저 Runtime.dbo.StorageLocation / StorageNode로 실제 History Storage 경로를 확인하고, 해당 경로의 총용량·파일수·드라이브 여유공간을 즉시 측정한다. 용량이 감당 가능하면 History Storage 원본을 통째로 인수하는 방향을 우선 검토하고, 원본 인수가 어렵거나 지나치게 크면 그때 Runtime.dbo.History 장기 Export로 전환한다. 구조 분석은 병행하여 DDE Item(MW주소) ↔ XG5000 Symbol/Comment/Program Block JOIN을 진행

현재 핵심 구조

flowchart LR
    PLC["LS ELECTRIC XGT PLC 계층<br/>PCS + 공정 PLC + FCC 24개"] -->|"FEnet / XGT Ethernet<br/>상위 DXP는 TCP 2004"| DXP["DeviceXPlorer 5.4.0.1"]
    DXP -->|"광암 상위 통신경로<br/>GFENet/SuiteLink 관계 확인 필요"| IT["Wonderware InTouch 2014 R2 SP1"]
    DXP -.->|"OPC 경유 가능성<br/>사용 여부 미확정"| FSG["FS Gateway 3.0 SP1"]
    FSG -.-> IT
    IT --> ALM["WWALMDB<br/>Alarm / Event SQL DB"]
    IT --> HISTCFG["Historian Runtime DB<br/>Tag/Storage 메타 + History 조회 인터페이스"]
    HISTCFG -->|"Runtime.dbo.History SELECT<br/>실제 값 조회 확인"| HISTDATA["Historian History Storage / Storage Engine<br/>원본 파일은 미인수"]
    IT -.-> LGH["InTouch LGH/IDX<br/>자체 History 사용 여부 확인"]
    HISTDATA --> MASTER["AI Master DB"]

현재 가장 중요한 구분은 WWALMDB ≠ Historian Runtime DB ≠ 실제 History Storage 이다. WWALMDB는 알람/이벤트이며, Runtime은 Tag/Storage 메타데이터와 History 조회 인터페이스를 제공한다. 운영 POS11에서는 Runtime.dbo.History를 통해 실제 공정 시계열 값 조회가 확인됐지만, 그 장기 데이터 원본/Export는 아직 우리에게 인수되지 않았다.

2026-09-09 POS11 Runtime.dbo.History 실조회 사진 확인 — v8

현장 SSMS 사진에서 다음이 직접 확인됐다.

  • SQL Server 노드: POS11
  • 선택 Database: Runtime
  • Object Explorer에 A2ALMDB / Holding / ReportServer / ReportServerTempDB / Runtime / WWALMDB 존재
  • 쿼리에서 FROM History
  • Historian 전용 조회조건:
    • wwRetrievalMode = 'Cyclic'
    • wwCycleCount = 100
    • wwQualityRule = 'Extended'
    • wwVersion = 'Latest'
  • 조회 Tag: PCS5_HV1A_2_TA
  • 결과 Grid에서 TagName / DateTime / vValue / MinRaw / MaxRaw / MinEU / MaxEU / Unit / Quality가 실제 반환됨

따라서 다음은 확정으로 올린다.

광암 POS11의 Wonderware Historian은 Runtime.dbo.History SQL 조회 인터페이스를 통해 실제 공정 시계열 값을 조회할 수 있다.

다만 사진만으로 실제 장기 값이 저장된 물리 파일의 정확한 위치를 확정할 수는 없다. D:\Historian\Data\Circular / Buffer / Permanent는 기존 Historian Export/설정 근거와 일치하므로 실제 History Storage 후보 경로로 유지하되, 현재 서버의 StorageLocation.Path 또는 파일시스템으로 최종 확인한다.

2026-09-09 Historian 원본 확보 전략 — v9

현장 작업시간이 짧다는 제약을 반영하여, AI 학습데이터 확보 순서를 장기 SQL Export 우선에서 History Storage 위치/용량 확인 → 원본 인수 가능성 판단으로 변경한다.

현재 판단

  • 자료로 확인됨: POS11 Runtime.dbo.History에서 실제 공정 시계열 값 조회 가능. Runtime DB에 StorageLocation, StorageNode 객체가 존재하며 2022 Historian Export에는 D:\Historian\Data\Circular / Buffer / Permanent 경로 근거가 있음.
  • 합리적 추정: 현재 POS11의 실제 장기 공정값은 Runtime SQL BAK 자체가 아니라 Historian History Storage 파일영역에 저장되어 있을 가능성이 높음.
  • 추가 확인 필요: 2026 현재 StorageLocation.Path 실제값, 해당 폴더 총용량, 파일수, 최초/최종 보존기간, 운영 중 원본 복제 방식.
  • 주의: 운영 중인 Historian Storage를 단순히 서비스 중지하거나 강제 복사하지 않는다. 서비스 중지는 현장 승인/운영영향 확인 후에만 검토한다.
