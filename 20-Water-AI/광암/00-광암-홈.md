# Water AI · 광암

## 현재 상태

- **현장 확인**: 2026-09-07 현장방문 완료
- **PLC 원본**: XG5000 `.xgwx` **155개 수집 완료(오류 0)**. 단, 동일 설비의 과거본/수정본/OLD가 포함되어 있어 155개를 PLC 155대로 해석하지 않음
- **PLC 구조**: PCS1/2/4/5/6, PCS_M, P22 약품, P23 오존, CO2, 염소 및 **FCC 24개 여과지 로컬 PLC** 계층 확인
- **PLC 통신망 명칭 보강**: 과거 제어망 문서에서 `192.9.211.x = LINE A`, `192.9.212.x = LINE B`로 직접 관리된 것을 확인. 2024/2026 설정에서도 두 대역이 반복되어 이중망 존재는 강하게 교차검증됨. 단 LINE A/B를 모든 설비의 Primary/Standby와 동일시하지 않음
- **PLC 과거이력**: PLC 자체 장기 백업 없음
- **HMI**: Wonderware **InTouch HMI 2014 R2 SP1 (v11.1)** 구성 확인
- **PLC 통신 미들웨어**: TAKEBISHI **DeviceXPlorer 5.4.0.1** 설정에서 `LsisEthernet` 13개 Device와 TCP `2004` 대상 확인
- **사전 제공 HMI 백업 대조**: 2023/2024 InTouch Application 백업 3개 계열이 존재하며, 2024-03-29 `dde.cfg`에서 **SuiteLink Application=`\\192.9.211.120\GFENet`** 및 P1/P2/P4/P6/P7/P8/P21/P22/P23/P25/P26/P27/P30 Topic을 직접 확인
- **POS11 정체 확인**: 과거 HUB/IP 문서에서 `192.9.211.120`과 `192.9.212.120` 모두 **감시제어 OS POS11**로 식별됨. 기존 `GFENet/VIEW` 상위 노드가 POS11 HMI 노드의 LINE A/B 주소라는 근거가 생김
- **HMI Tag DB 직접 확보**: `광암정수센터_HMI자료정리.xlsx`의 `광암_태그` Sheet가 `:IOAccess / :IODisc / :IOReal` 형식의 InTouch Tag DB Export 계열 자료임을 확인. `IODisc 10,146 + IOReal 4,724 = 14,870개` Tag 메타데이터 확보
- **History Logging 단서 강화**: IOReal 4,724개 중 **4,214개가 `Logged=Yes`**, IODisc 10,146개 중 **3,498개가 `AlarmState=On`**. Analog는 History Logging, Digital은 Alarm/Event 중심 성격이 강하게 보이나 `Logged=Yes`를 Wonderware Historian 저장으로 곧바로 동일시하지 않음
- **중요 정정**: `DXPSV`는 DeviceXPlorer Ver.5의 기본 Application Name이자 현장 확보 `.dxp` 파일명 단서일 뿐, **광암 InTouch의 실제 Application Name이 `DXPSV`라고 확정할 수 없음**. 사전 제공 2024 HMI 백업에서는 실제 값이 `GFENet`
- **HMI↔PLC 논리구조 대조**: 2024 HMI의 GFENet 13개 주 Topic이 2026 현장 DeviceXPlorer의 13개 Device 이름과 **완전 일치**. 따라서 동일 PLC 논리대상을 바라보는 구조는 강하게 교차검증됨
- **추가 HMI Source 역할 보강**: `P52`는 IOReal 417개 전부 Logged=No이며 `여과지동_P2P52`에 묶여 있어 **P2/여과지 계열 보조 Analog Topic** 근거가 강함. `P56`는 IOReal 72개 전부 Logged=No이며 **P6/활성탄 계열 보조 Analog Topic** 근거가 강함. `PLC3`는 `침전지 대표탁도 / MW2600` 1 Point. 별도 PLC 대수로 바로 해석하지 않음
- **InTouch 통신 포인트**: 2024 `dde.cfg`에서 GFENet 경유 포인트 **14,983개**, 전체 DDE Point **14,997개**를 추출
- **FSGateway**: 2024 InTouch에 `OPC → \\localhost\FSGateway / OPC_DeviceGroup` Source가 실제 정의되어 있으나 **Point 0개**. 적어도 이 백업 시점의 주 PLC 경로였다는 증거는 없음
- **211/212 이중 경로**: 2024 InTouch `INTOUCH` Source에서 `\\192.9.211.120\VIEW`를 Primary, `\\192.9.212.120\VIEW`를 Secondary로 직접 설정. 211/212 이중망이 실제 HMI 계층에서도 사용된 흔적은 확인됨. 단 이를 모든 PLC의 Primary/Standby 구조로 일반화하지 않음
- **History 기능**: `HistdataViewstr / HistData / ViewStream1`과 `aaHistClient*` ActiveX 구성으로 **History 조회 기능 자체는 확인**. 다만 2024 자료끼리도 HistData 주소가 `192.9.211.120`과 `192.168.0.120`으로 달라 현재 런타임 재확인이 필요하며, 실제 Wonderware Historian 저장 Tag/보존기간은 아직 미확정
- **알람 DB**: 기존 분석한 `WWALMDB`는 **InTouch Alarm DB Logger 계열의 알람·이벤트 SQL DB**로 분류. Historian 공정 시계열 DB와 구분
- **Tag 메타데이터 우선순위 변경**: `tagname.x` 원본은 여전히 유용하지만, 기본 Tag Type/Comment/Logged/Alarm/AccessName/ItemName은 `광암정수센터_HMI자료정리.xlsx`에서 이미 14,870개 확보했으므로 **Tag 분석 시작을 위해 tagname.x 재수집을 기다릴 필요는 없음**
- **P8 명칭 주의**: 과거 HUB 문서에서 `.18=관리본관 PCS-M_XGI`, `.19=PCS-M_XGI WATER NOW`로 분리되어 있어 기존 `P8(.18)=WaterNow` 표현은 확정에서 내림. 2026 DXP/XG5000 기준 재확인 필요
- **다음 작업 1순위**: `14,870개 HMI Tag ↔ XG5000 PLC Address Dictionary` JOIN + 현재 2026 InTouch DBDump/DXP Application 확인 + `dhistcfg.ini / historian.txt / 실제 Historian Export`로 장기 저장계층 확정

## 현재 핵심 구조 — 시점 분리

```mermaid
flowchart LR
    PLC["LS ELECTRIC XGT PLC 계층<br/>PCS + 공정 PLC + FCC"] -->|"2026 현장 설정<br/>LsisEthernet / TCP 2004"| DXP["DeviceXPlorer 5.4.0.1<br/>13개 Device<br/>POS11 211.120 측 설정"]
    PLC -->|"2024 HMI 백업<br/>SuiteLink Topic"| GF["GFENet<br/>POS11 LINE A<br/>\\192.9.211.120\\GFENet"]
    DXP -.->|"GFENet이 DXP의 사용자정의 Application인지<br/>별도/구형 서버인지 확인 필요"| GF
    GF --> IT["Wonderware InTouch HMI<br/>광암아리수정수센터<br/>POS11: 211.120 / 212.120"]
    FSG["FSGateway<br/>OPC Source는 있으나 Point 0"] -.-> IT
    IT --> ALM["WWALMDB<br/>Alarm / Event SQL DB"]
    IT --> HD["HistData ViewStream<br/>History 조회 구성 확인<br/>주소 자료간 불일치"]
    IT -.-> HIST["Wonderware Historian Server<br/>실제 Tag/Storage는 추가 확인"]
    HIST --> MASTER["AI Master DB"]
```

> 현재 가장 중요한 정리는 두 가지다.  
> 1) **`WWALMDB ≠ Historian`**  
> 2) **`DXPSV`를 광암의 실제 InTouch Application Name으로 확정하면 안 된다. 2024 HMI 백업에서는 `GFENet`이 직접 확인된다.**

## 정수 AI 개발 원칙

광암은 **정수 AI 학습·검증 기준 시설**이다.

```text
광암정수장 장기 운전데이터
→ Historian/기존 저장계층 확인
→ AI Master DB
→ 정수 수요·수질·약품·전력 분석
→ 정수 AI 예측/최적화 모델 개발
→ 모델 검증 및 표준화
→ 명장 최종 적용장에 적용
```

PLC 자체에 과거이력이 없으므로 실제 학습데이터는 **Wonderware Historian 또는 별도 History 저장계층**에서 확보해야 한다. 사전 HMI 백업에서 History 조회 기능은 확인됐지만, 실제 장기 저장소와 보존기간은 별도로 증명한다.
