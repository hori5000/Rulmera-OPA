# 광암 `PLC → 통신서버 → InTouch → History/DB` 실제 연결 확인 위치

## 0. 목적

2026 현장자료와 2023/2024 사전 제공 HMI 백업을 대조한 결과, 예전보다 훨씬 많은 구간이 파일로 확인됐다.

이제는 “무슨 소프트웨어가 있을까?”보다 **시점별 실제 연결을 확정하고, 2024 백업과 2026 현재 구성이 어떻게 이어지는지**가 핵심이다.

```text
A0. 현장 신호 → PLC 주소/프로그램/PLC간 전송
A.  PLC → 2026 DeviceXPlorer
B.  PLC/통신서버 → 2024 InTouch GFENet Source
C.  2024 GFENet ↔ 2026 DeviceXPlorer 관계
D.  InTouch → History/Historian
E.  InTouch Alarm → WWALMDB
```

---

# 1. 현재 결론 판별표

| 구간 | 현재 확인된 것 | 아직 필요한 것 | 판정 |
|---|---|---|---|
| PLC 내부 | XG5000 155개 원본 | 현재본 정규화 | **분석 가능** |
| PLC→2026 DXP | `LsisEthernet`, 13 Device, TCP 2004 | 런타임 파일/GUI 일치 확인 | **매우 강함** |
| 2024 HMI PLC Source | `GFENet`, SuiteLink, 14,983 Point | 서버 제품 정체 | **확정** |
| 13개 주요 Topic | 2024 GFENet와 2026 DXP 이름 완전 일치 | 현재/과거 관계 확인 | **강한 교차검증** |
| Application=`DXPSV` | 직접 근거 없음 | 현재 DXP GUI 확인 | **미확정** |
| FSGateway | HMI Source 정의 있음 | 현재 사용 여부 | **정의 확인 / Point 0** |
| 211/212 | HUB 문서 `LINE A/LINE B` + InTouch VIEW Primary/Secondary | 전체 설비별 이중화 방식 | **망 명칭 확정 / 역할은 설비별 확인** |
| POS11 | `211.120/212.120` | GFENet/DXP와의 현재 관계 | **감시제어 OS POS11로 식별** |
| HMI Tag DB | IODisc 10,146 / IOReal 4,724 | 2026 현재 변경분 | **2024 메타데이터 확보** |
| HistData | ViewStream1 13 Point | 실제 저장소 | **조회 구성 확인** |
| Historian | 제품 설치/구성요소 확인 | Tag/Storage/기간 | **미확정** |
| WWALMDB | Alarm DB 계열로 강하게 일치 | Logger 설정 | **강한 확정 수준** |

# 2. A0 — `현장 신호 → PLC`

XG5000 `.xgwx` 155개 수집본으로 분석한다.

필수 정규화 컬럼:

```text
PLC Canonical ID
현재본 후보
Project File / Project Name
CPU / Module / Slot
211.x / 212.x IP
Program Block
Symbol / Comment
%IX / %IW / %MX / %MW / %QX
High-speed Link / Network 송수신 영역
AUTO/MANUAL / PID / Interlock / Alarm
```

특히 PCS2↔FCC 24개는 통신 Word까지 추출한다.

세부: [[04-광암-PLC-XG5000-구조-및-통신맵]]

# 3. A — `PLC → 2026 DeviceXPlorer`

현장 확보 설정:

```text
DXPSV.dxp
ProductVersion = 5.4.0.1
LibType = LsisEthernet
Device = P1/P2/P4/P6/P7/P8/P21/P22/P23/P25/P26/P27/P30
Remote TCP Port = 2004
```

현재 확인할 것:

1. 이 `.dxp`가 현재 런타임 파일인지
2. 각 Device가 Online인지
3. DeviceXPlorer의 **DDE/SuiteLink Application Name**
4. Topic Name
5. `192.9.211.120` NIC/서버 역할

> 예전처럼 `DXPSV`가 기본값이라는 이유만으로 실제 Application Name을 `DXPSV`라고 기록하지 않는다.

# 4. B — `2024 InTouch → GFENet`

사전 제공 최신 HMI 백업:

```text
HMi backup\광암아리수정수센터_POS11_2024.03.29
```

`INTOUCH.INI`:

```text
AppName0=광암아리수정수센터
```

`dde.cfg`:

```text
Application Name = \\192.9.211.120\GFENet
SuiteLink = 1
```

13개 주요 Source:

```text
P1/P2/P4/P6/P7/P8/P21/P22/P23/P25/P26/P27/P30
```

추가 Source:

```text
P52/P56/PLC3
```

GFENet Point:

```text
14,983개
```

`dde.cfg`의 각 Point는 다음 형태를 갖는다.

```text
InTouch Tag
→ Source
→ Application
→ Topic
→ Item(MWxxxx 등)
```

따라서 **PLC 주소 매핑의 상당 부분은 이미 확보됐다.**

# 5. C — `GFENet ↔ DeviceXPlorer` 관계 확인

현재 가장 중요한 미확정 항목이다.

### 확인된 공통점

```text
2024 GFENet Topic 13개
=
2026 DeviceXPlorer Device 13개
```

정확히 일치한다.

### 아직 모르는 것

아래 중 어느 경우인지 확인해야 한다.

```text
1. DeviceXPlorer의 SuiteLink Application Name을 GFENet으로 사용자 정의해 사용
2. 과거 GFENet 서버를 사용하다가 이후 DeviceXPlorer로 전환
3. GFENet과 DeviceXPlorer가 동시에 존재하며 역할이 다름
4. 백업 시점/서버 노드가 달라 서로 다른 구성
```

### 현재 확인 방법

DeviceXPlorer GUI:

```text
Tools / Options
→ DDE/SuiteLink
→ Application Name
```

Windows 프로세스/서비스:

```powershell
Get-Process | Where-Object {
  $_.ProcessName -match 'DXP|GFENet|FSGateway|view|hist'
} | Select-Object ProcessName, Id, Path

Get-Service | Where-Object {
  $_.DisplayName -match 'DeviceX|GFENet|Wonderware|Historian|Gateway'
} | Select-Object Status, Name, DisplayName
```

파일 검색:

```powershell
Get-ChildItem C:\ -File -Recurse -ErrorAction SilentlyContinue |
  Where-Object { $_.Name -match 'GFENet|DXPSV|\.dxp$' } |
  Select-Object FullName, LastWriteTime, Length
```

# 6. FSGateway 판정

2024 `dde.cfg`:

```text
Source Name = OPC
Application Name = \\localhost\FSGateway
Topic Name = OPC_DeviceGroup
Point = 0
```

따라서:

- FSGateway가 HMI 구성에 **정의된 것은 확정**
- 하지만 해당 백업에서 실제 Point는 없음
- 주 PLC Source는 `GFENet` 14,983 Point

현재 확인할 것은 “2026에 다른 용도로 쓰는가”다.

---

# 7. 211 / 212 이중 경로

`dde.cfg`:

```text
Source Name = INTOUCH

Primary:
\\192.9.211.120\VIEW
TAGNAME

Secondary:
\\192.9.212.120\VIEW
TAGNAME
```

이것은 **HMI Source 수준의 Primary/Secondary 구성**을 직접 보여준다.

따라서 211/212가 이중화 성격을 갖는다는 근거는 강화됐지만, 모든 PLC 통신까지 동일한 구조라고 단정하지 않는다.

# 8. D — `InTouch → History/Historian`

## 8.1 새로 직접 확인된 History Source

```text
Source Name = HistdataViewstr
Application Name = \\192.9.211.120\HistData
Topic Name = ViewStream1
Point = 13
```

또한 HMI Application에는 다음 ActiveX가 있다.

```text
aaHistClientQuery
aaHistClientTrend
aaHistClientTagPicker
aaHistClientSingleValueEntry
HistClient
```

즉 **과거값 조회/Trend 기능은 HMI에 구성돼 있었다.**

## 8.2 아직 구분해야 할 것

```text
InTouch 자체 Historical Logging
vs
Wonderware Historian Server
```

둘을 혼동하지 않는다.

### HMI Tag DB는 이미 상당 부분 확보

`광암정수센터_HMI자료정리.xlsx → 광암_태그`에서 다음을 이미 직접 확보했다.

```text
Tag Type / Comment / Logged / EventLogged
AccessName / ItemName / ReadOnly
Digital AlarmState
Analog EU/Alarm 필드
```

따라서 `tagname.x` 재수집은 **분석 시작의 선행조건이 아니다.** 현재 14,870개 Tag로 PLC 주소 JOIN을 먼저 진행한다.

### 기존 사전자료 트리에서 이미 존재가 확인된 파일

Upload-Lite `00_ALL_FILES.csv` 기준:

```text
HMi backup\historian.txt
...\dhistcfg.ini
...\tagname.x
...\tagnames.ndx
```

현재 ZIP에는 용량/선별 제한으로 빠졌으므로 **원본에서 재수집**한다.

### 우선 확보

1. `historian.txt`
2. `dhistcfg.ini`
3. **현재 2026 InTouch DBDump CSV** — 2024 Tag DB와 변경 비교
4. Historian SMC Tag/Storage Export
5. `alarm.cfg`
6. `tagname.x / tagnames.ndx` — 원본 보강/검증용

---

# 9. E — `InTouch Alarm → WWALMDB`

사전 원본 트리에 `alarm.cfg`가 존재하는 것도 확인됐다.

Upload-Lite에서는 미포함이므로 다시 뽑는다.

확인 목표:

```text
Alarm DB Logger Server
Database = WWALMDB ?
Query
Logging Mode
Alarm Group
```

이 파일/설정을 기존 WWALMDB BAK 구조와 대조하면 최종 확정할 수 있다.

---

# 10. 기존 제공자료에서 먼저 다시 뽑을 파일

현장 재방문 전에 아래부터 수집한다.

| 우선순위 | 파일 | 이유 |
|---:|---|---|
| 1 | `dhistcfg.ini` | InTouch History 저장/경로 설정 확인 |
| 2 | `historian.txt` | Historian 관련 기존 제공자료 분석 |
| 3 | 현재 2026 DBDump CSV | 2024 HMI Tag DB와 변경분 비교 |
| 4 | `alarm.cfg` | Alarm DB Logger/Alarm 설정 보강 |
| 5 | `tagname.x / tagnames.ndx` | 원본 Tag DB 검증·보강 |
| 6 | 2023 `dde.cfg` | 2024와 비교해 구조 변경 이력 확인 |
| 7 | Historian SMC Export | 실제 저장 Tag/Storage 확정 |

> Upload-Lite의 원본 파일목록에서 존재가 확인됐으므로, 이 항목들은 우선 **기존 전달자료 재수집 작업**이다.

| 2024-03-29 | ... | ... | ... | ... | ... | P1 | GFENet | P1 | ... | MW... | ... | ... | confirmed/inferred |
