# 2026-09-09 제어설비 IP 및 HMI 자료정리 대조 기록

## 결론

기존 광암 Obsidian의 큰 구조는 유지한다. 다만 이번 두 Excel 자료로 **네트워크와 HMI Tag DB에 대한 직접 근거가 크게 늘었고 일부 표현은 수정해야 한다.**

### 새로 확정 또는 강화된 내용

- `192.9.211.x = LINE A`, `192.9.212.x = LINE B`라는 과거 네트워크 관리 명칭
- `192.9.211.120 / 192.9.212.120 = 감시제어 OS POS11`
- HMI `광암_태그`가 `:IOAccess / :IODisc / :IOReal` 구조의 InTouch Tag DB Export 계열 자료
- IODisc 10,146개 + IOReal 4,724개 = 14,870개 Tag 메타데이터 확보
- IOReal 4,214개가 `Logged=Yes`
- IODisc 3,498개가 `AlarmState=On`
- P52는 P2/여과지 계열 보조 Analog Topic 성격이 강함
- P56는 P6/활성탄 계열 보조 Analog Topic 성격이 강함
- PLC3는 `침전지 대표탁도 / MW2600` 1 Point
- Workbook에 26개 HMI 화면 이미지가 포함됨

### 새로 생긴 충돌/확인 필요

- HistData Application 주소가 자료에 따라 `192.9.211.120`과 `192.168.0.120`으로 다름
- P8 `.18`의 명칭이 기존 WaterNow 해석과 과거 HUB 문서의 `PCS-M_XGI` 표기가 충돌
- 과거 HUB 문서의 AOP LINE B는 `192.168.80.2 예정`으로 기록되어 있어 A/B 완전 대칭 구조로 일반화할 수 없음

## 자료 성격

### HUB PORT 정보

과거망 문서다. 현재 2026 설정과 직접 대조할 때만 확정 근거로 승격한다.

### HMI자료정리

2024-05-02 수정된 수기 정리 Workbook이지만 `광암_태그` Sheet는 InTouch Tag DB Export 구조가 포함돼 있어 **통신/Tag 메타데이터 근거 가치가 높다.**

단 공정별 Sheet는 사람이 다시 분류한 자료라 서로 다른 AccessName Tag가 섞일 수 있으므로 원천 통신 구조 판단에는 사용하지 않는다.

## 기존 Obsidian 변경 원칙

### 유지

```text
PLC → 통신 미들웨어 → InTouch → History/Alarm DB → AI Master DB
```

### 수정

```text
211/212 = 미상 이중망
→ 과거 문서상 LINE A / LINE B로 명시

192.9.211.120 = 단순 상위노드
→ POS11 감시제어 OS의 LINE A 주소
192.9.212.120 = POS11 감시제어 OS의 LINE B 주소

P52/P56 = 정체불명 추가 Topic
→ 각각 P2/여과지, P6/활성탄 보조 Analog Topic이라는 근거 강화

Tagname.x가 있어야 Tag 메타데이터 분석 시작 가능
→ HMI자료정리의 광암_태그 Sheet로 14,870개 IODisc/IOReal 메타데이터 이미 확보
```
