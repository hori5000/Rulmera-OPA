## 4. 기존 Obsidian에서 수정해야 할 것

### 4.1 `Application=DXPSV` 추정

기존 문서에서는 DeviceXPlorer Ver.5 기본 Application Name이 `DXPSV`이고 파일명도 `DXPSV.dxp`라는 점을 근거로, InTouch가 `DXPSV`로 직접 붙을 가능성이 높다고 봤다.

하지만 2024 HMI `dde.cfg`에는 실제 값이 명시돼 있다.

```text
Application Name = \\192.9.211.120\GFENet
```

따라서:

```text
DXPSV = 제품 기본값/파일명 단서
GFENet = 2024 HMI에서 직접 확인된 실제 Application
```

로 수정한다.

`DXPSV`를 광암 실제 Application Name으로 기록하지 않는다.

### 4.2 FSGateway

기존에는 설치 바이너리만 확인되어 실제 사용 여부가 미확정이었다.

2024 `dde.cfg`:

```text
Source Name = OPC
Application Name = \\localhost\FSGateway
Topic Name = OPC_DeviceGroup
Point = 0
```

즉 FSGateway Source가 **정의된 것은 확정**됐지만, 이 백업에서 실제 Point는 없다.

따라서 주 PLC 데이터 경로였다는 근거는 오히려 약하다.

### 4.3 InTouch Access/Item 정보

기존에는 DBDump가 없어서 Access/Item을 거의 모른다고 봤다.

하지만 `dde.cfg`에서 다음을 직접 추출할 수 있다.

```text
Source
Application
Topic
InTouch Tag
Item(MWxxxx)
```

GFENet 기준 **14,983개 Point**가 있다.

따라서 PLC↔HMI 데이터계보 작업을 바로 시작할 수 있다.

## 5. 새로 발견된 것

### 5.1 추가 GFENet Source

```text
P52
P56
PLC3
```

이 3개는 2026 DeviceXPlorer 13개 Device 목록에는 없다.

현재는 별도 PLC로 확정하지 않는다.

- P52: PCS2/FCC/여과 관련 Tag가 많음
- P56: PCS6/활성탄 관련 Tag가 많음
- PLC3: 1 Point

과거/보조/별도 Topic 가능성을 확인한다.

### 5.2 211/212 Primary/Secondary

2024 `INTOUCH` Source:

```text
Primary   = \\192.9.211.120\VIEW
Secondary = \\192.9.212.120\VIEW
```

따라서 211/212 이중망이 실제 HMI Source 구성에 사용됐다는 직접 근거가 생겼다.

단, 이 사실만으로 모든 PLC 211/212를 Primary/Standby라고 확정하지 않는다.

### 5.3 History 조회 기능

`dde.cfg`:

```text
HistdataViewstr
→ \\192.9.211.120\HistData
→ ViewStream1
→ 13 Point
```

`itocx.cfg / itguid.cfg`:

```text
aaHistClientQuery
aaHistClientTrend
aaHistClientTagPicker
HistClient
AlmDbViewCtrl
```

따라서 HMI에 History 조회/Trend 기능이 구성된 것은 확인됐다.

다만 실제 장기 저장소가 InTouch 자체 History인지 Wonderware Historian인지, 또는 둘 다인지 추가 확인한다.

### 5.4 HMI 화면/기능 범위

`OrgHeir.xml`에서 다음 화면군이 확인된다.

```text
정수장계통도
정수생산계통도
중계펌프장
PAC투입설비
CO2
오존
염소
여과지
활성탄흡착지
전력감시
원수유량제어
역세척
알람
트렌드
```

정수 AI에서 필요한 수량·약품·펌프·전력·여과 운전변수를 HMI가 폭넓게 다루고 있었다는 구조적 근거다.

## 8. 최종 판단

**현재 Obsidian을 폐기하거나 새로 만들 필요는 없다.**

큰 구조는 현장자료와 사전자료가 서로 잘 맞는다.

다만 기존 Obsidian은 2026-09-09 기준으로 다음 원칙으로 보정한다.

```text
2026 현장자료 = 현재 상태 우선 근거
2023/2024 HMI 백업 = 과거 구조 교차검증 근거
둘이 일치하면 신뢰도 상승
둘이 다르면 시점 차이/구성 변경으로 기록
```

따라서 **현재 Vault를 유지하면서 시점과 근거 수준을 더 엄격하게 관리하는 것이 맞다.**
