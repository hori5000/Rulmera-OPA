# 프로젝트 헌장 v0.5

> [!summary]
> 이 문서는 프로젝트 관리 기준, 책임, 일정, 통제 절차를 정리한 관리 문서다.

> [!info]
> 표기 기준: 전문 용어는 가능하면 `원어(알기 쉬운 설명)` 형식을 사용하고, 공통 기준은 [[20-설계/00-용어-스타일-가이드]]를 따른다.

## 1. 프로젝트명
**Rulmera OPA Enterprise Knowledge**

## 2. 총괄 및 핵심 역할
- 프로젝트 총괄/PM/제품책임자: **룰메라팀 윤석훈 팀장**
- 개발: **윤석훈 팀장 — AI/RAG, Backend, Frontend, OPA/보안, DB, 인프라, 시험, Android, 배포 Fabric 포함**
- 마케팅·영업: **룰메라팀 김일형 / 코이넷 대표**
- PoC 고객 기술책임자: 미정

## 3. 목적

기술중소기업의 문서·설계·소스·매뉴얼·장애이력과 숙련자의 암묵지를 회사 지식으로 정본화하고, 사용자의 인가에 따라 허용된 지식만 검색하여 **근거와 원문 링크까지 제공하는 사내 AI 선임자**를 제품화한다.

단, 구축 시점의 지식을 한 번 넣고 끝나는 제품이 아니라, 회사가 새 프로젝트를 계속 수행하더라도 **자료 저장만으로 지식이 계속 갱신되는 운영 플랫폼**을 목표로 한다.

## 4. 제품 비전

> **사용자는 Rulmera 웹에서 직접 문서를 보거나 텍스트/음성으로 회사 AI에게 질문한다. OPA가 먼저 권한을 판정하고, Qwen은 허용된 승인 지식을 기반으로 답한다. 답변은 Rulmera 템플릿 안에서 일관되게 표시되며 근거를 눌러 실제 원문으로 이동한다.**

## 5. 목표
1. OPA가 회사/부서/업무/프로젝트/인가를 Qwen보다 먼저 판정.
2. L0~L5 + RBAC/ABAC로 DENY 자료를 Retrieval에서 차단.
3. 승인된 정본만 RAG 대상으로 사용.
4. 답변에 Citation/버전/충돌/Deep Link 제공.
5. Qwen은 HTML/UI가 아니라 구조화된 Answer Contract 반환.
6. 텍스트와 음성 질문을 동일한 보안/RAG 경로로 처리.
7. 지정 Source의 신규/변경 파일을 자동 감지·분류·증분 색인.
8. 신규 프로젝트를 Project Candidate로 감지해 승인 후 정식 등록.
9. 중요자료는 사람 승인, 저위험자료는 정책기반 자동승인 가능.
10. 새 사실은 반복 재학습보다 RAG 갱신을 우선.
11. A6000 48GB 기반 Private Qwen-class LLM PoC 구현.
12. Web/PWA/Android 동일 UI 코드베이스.
13. **One Release → Cloudflare / On-Prem / Customer Cloud** 배포 이식성 확보.
14. 10영업일 Vertical Slice PoC로 핵심 위험을 먼저 검증.

## 7. 성공기준
- 권한 위반/금지자료 노출: **0건**
- 적용대상 답변 출처 표시: **100%**
- Citation Deep Link 유효성: **100% 시험케이스**
- Golden 50 전문가 기준 유용 답변: **80%+ 초기목표**
- No-evidence 안전응답: **90%+**
- 승인 전 고위험 지식 RAG 노출: **0건**
- 신규/변경문서 증분 반영 E2E 확인
- 신규 Project Candidate 생성/승인/연결 확인
- Cloudflare/On-Prem Core API/OPA/Citation Parity 확인

## 9. 기술 기준
- GPU: NVIDIA RTX A6000 48GB
- LLM: Qwen 20~30B급 우선 후보
- DB: PostgreSQL + pgvector
- Policy: OPA
- Frontend: React + TypeScript + Vite
- Backend: FastAPI
- Deployment: Docker Compose PoC → 환경별 Adapter/Profile
- Object: S3-compatible abstraction
