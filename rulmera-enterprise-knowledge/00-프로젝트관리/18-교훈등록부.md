# 교훈 등록부 v0.5

> [!summary]
> 이 문서는 프로젝트 관리 기준, 책임, 일정, 통제 절차를 정리한 관리 문서다.

> [!info]
> 표기 기준: 전문 용어는 가능하면 `원어(알기 쉬운 설명)` 형식을 사용하고, 공통 기준은 [[20-설계/00-용어-스타일-가이드]]를 따른다.

| ID | 상황 | 교훈 | 다음 적용 |
|---|---|---|---|
| LES-001 | 프로젝트 착수 | 큰 시스템보다 10일 Vertical Slice로 핵심위험을 먼저 확인 | 모든 큰 기능을 E2E 최소형으로 연결 |
| LES-002 | Web+Android | 1인 개발에서 별도 Native UI는 유지비가 큼 | Responsive Web + Capacitor |
| LES-003 | LLM/보안 | Prompt 금지지시는 보안경계가 아님 | OPA→Retrieval 순서 고정 |
| LES-004 | 모델 선택 | 모델 파일크기와 실제 GPU 효율은 다름 | 실제 커널/양자화/Latency 벤치 |
| LES-005 | 기업지식 | 초기 지식품질이 좋아도 회사는 계속 변함 | Continuous Ingestion + Incremental RAG |
| LES-006 | 자동화 | 완전자동 승인은 기업 기밀에서 위험 | AI는 후보, 고위험은 사람 승인 |
| LES-007 | UI | LLM이 HTML을 생성하면 템플릿/검증성이 흔들림 | Versioned Answer Contract |
| LES-008 | Citation | 절대 URL은 배포환경 변경 시 깨짐 | Logical Resource + Route Resolver |
| LES-009 | 배포 | Cloudflare/On-Prem 별도 Fork는 장기 유지비를 키움 | Deployment Profile/Adapter |
| LES-010 | 플랫폼 호환 | workerd/R2 호환성을 Cloudflare 전체와 동일하다고 보면 위험 | 필요한 계약만 추상화하고 Parity test |
