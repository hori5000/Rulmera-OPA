# 클라이언트 UI 설계 v0.4 — Rulmera가 화면을 소유한다 v0.5

> [!summary]
> 이 문서는 제품 구조, 데이터 흐름, 권한 구조, 동작 원리를 설명하는 설계 기준 문서다.

> [!info]
> 표기 기준: 전문 용어는 가능하면 `원어(알기 쉬운 설명)` 형식을 사용하고, 공통 기준은 [[20-설계/00-용어-스타일-가이드]]를 따른다.

## 선택
**React + TypeScript + Responsive CSS + PWA + Capacitor Android**

## 핵심 원칙
> [!important]
> **Qwen 출력이 곧 화면이 되면 안 된다.**  
> Qwen은 HTML/레이아웃을 생성하지 않고, Rulmera가 정의한 `Answer Contract(표준 응답 규격)`를 반환한다.

이를 통해:
- 회사별 답변 화면이 흔들리지 않는다.
- Cloudflare / On-Prem에서도 동일한 UI를 유지한다.
- Citation / 보안 Badge / 충돌경고를 강제할 수 있다.
- 모델을 바꿔도 제품 UI는 그대로 유지된다.

## 일반 사용자가 보는 답변 구성
- **답변 본문**: 질문에 대한 쉬운 설명
- **요약**: 핵심만 짧게
- **다음 확인사항**: 실무자가 바로 체크할 다음 단계
- **보안/인가 표시**: 내 권한 기준 표시
- **근거 개수**: 몇 건의 문서를 근거로 썼는지
- **출처 목록**: 어떤 문서를 참조했는지
- **경고 표시**: 충돌 / 구버전 / 승인상태 주의
- **관련 문서**: 더 읽을 자료
- **원문 Deep Link**: 정확한 문서 위치 이동

## Source Panel(근거 패널) 예시
```text
[근거 1] M203 송풍기 제어 / Rev.4 / p.17
상태: 승인본 · L3 · 현재 유효
[원문 위치 열기]

[근거 2] 장애사례 #241
상태: 승인본 · L2
[사례 열기]
```

## Voice(음성질의)
- Web Speech / STT 또는 사내 STT Adapter를 교체 가능하게 설계
- STT Text(음성을 문자로 바꾼 결과)를 사용자에게 보여주고 수정 허용
- 전송 이후 `/query` 처리 경로는 키보드 입력과 동일
- 음성 원문 저장 여부는 Tenant 정책으로 결정

## Deployment-neutral UI(배포환경 독립 UI)
Frontend는 환경별 절대 URL을 하드코딩하지 않는다.

```text
citation.resource_id
  ↓
GET /api/routes/resolve?resource_id=...
  ↓
현재 Profile에 맞는 URL
```

## 반응형 화면 원칙
- **Desktop**: Sidebar + Main + Evidence Panel
- **Tablet**: 축약 Sidebar + Drawer
- **Mobile**: Top bar + Bottom Nav + Bottom Sheet
- **Android**: 동일 Build를 Capacitor로 패키징

## 개발 순서
1. Mock Answer Contract(가짜 응답 규격으로 화면 검증)
2. Streaming Chat
3. Citation / Deep Link
4. Voice / STT
5. Identity / OPA Badge
6. Knowledge Inbox / Approval
7. Cloudflare / On-Prem UI Parity
8. Android package
