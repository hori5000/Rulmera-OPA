# 전체 아키텍처 v0.3

## 설계 핵심

Rulmera OPA Enterprise는 **지식운영 Core**와 **배포환경 Adapter**를 분리한다.

```mermaid
flowchart TB
  subgraph Sources[Enterprise Sources]
    FS[파일서버/NAS/지정폴더]
    GIT[Git/소스저장소]
    EXT[향후 SharePoint/DMS]
  end

  subgraph Ingestion[Continuous Knowledge]
    WATCH[Source Watcher]
    EXTRACT[Extract/OCR]
    CLASS[AI Classifier<br/>문서종류·프로젝트·보안·버전]
    CAND[Knowledge / Project Candidate]
    APPROVE[Approval]
  end

  subgraph Client[Rulmera Client]
    WEB[Browser/PWA]
    AND[Android Capacitor]
    VOICE[Voice/STT]
  end

  subgraph App[Rulmera Core]
    API[Application API]
    AUTH[Identity Adapter]
    OPA[Open Policy Agent]
    ROUTE[Logical Route Resolver]
    AUD[Audit Service]
    CONTRACT[Answer Contract]
  end

  subgraph Knowledge[Knowledge Layer]
    PG[(PostgreSQL + pgvector)]
    OBJ[(Object Storage Adapter)]
    RR[Reranker]
  end

  subgraph AI[Private AI]
    LLM[Qwen-class LLM]
    EMB[Embedding Model]
  end

  subgraph Deploy[Deployment Fabric]
    DCF[Cloudflare Profile]
    DOP[On-Prem Profile]
    DCC[Customer Cloud Profile]
  end

  FS --> WATCH
  GIT --> WATCH
  EXT --> WATCH
  WATCH --> EXTRACT --> CLASS --> CAND --> APPROVE
  APPROVE --> OBJ
  APPROVE --> EMB --> PG

  VOICE --> API
  WEB --> API
  AND --> API
  API --> AUTH --> OPA
  OPA -->|authorized filters| PG
  PG --> RR --> LLM
  LLM --> CONTRACT --> API
  API --> ROUTE
  API --> AUD

  DCF -.hosts.-> WEB
  DOP -.hosts.-> WEB
  DCC -.hosts.-> WEB
```

## 요청 처리 순서

```mermaid
sequenceDiagram
  participant U as User
  participant UI as Rulmera UI
  participant O as OPA
  participant R as Retrieval
  participant Q as Qwen
  participant L as Route Resolver

  U->>UI: 텍스트/음성 질문
  UI->>O: identity + question metadata
  O-->>UI: authorized scope / deny
  UI->>R: scope + question
  R-->>Q: 승인된 근거 Context
  Q-->>UI: Structured Answer Contract
  UI->>L: citation resource_id
  L-->>UI: 현재 배포환경의 원문 URL
  UI-->>U: 답변 + 근거 + 원문 링크
```

## 기술선택 기준
- Frontend: React + TypeScript + Vite + PWA
- Android: Capacitor
- Backend: Python FastAPI
- Policy: Open Policy Agent (Rego)
- DB: PostgreSQL + pgvector
- Object: S3-compatible abstraction
- Model serving: 실제 A6000 벤치 후 선택
- Streaming: SSE 우선
- Container: Docker Compose PoC, 운영은 환경별 확장
- Edge/Web Adapter: Cloudflare Workers/Static Assets 또는 On-Prem Web Gateway
- `workerd`: Workers 호환이 필요할 때 **선택적** 사용

## 경계 원칙

### Core에 들어가는 것
- Identity/OPA 계약
- Knowledge Metadata
- Approval State
- Retrieval
- Citation
- Answer Contract
- Logical Route
- Audit

### Adapter로 분리하는 것
- Cloudflare Workers binding
- R2 endpoint/credentials
- On-Prem reverse proxy
- Customer Cloud ingress/load balancer
- 플랫폼별 secret/config

> [!warning]
> `workerd`는 Cloudflare Workers와 같은 계열 런타임이지만, Cloudflare 전체 플랫폼을 복제하는 것은 아니다. 자체 서비스 시 보안 경계는 VM/container/network 정책과 함께 구성한다.
