# 용어·스타일 가이드 v0.5

> [!summary]
> 이 문서는 제품 구조, 데이터 흐름, 권한 구조, 동작 원리를 설명하는 설계 기준 문서다.

> [!info]
> 표기 기준: 전문 용어는 가능하면 `원어(알기 쉬운 설명)` 형식을 사용하고, 공통 기준은 [[20-설계/00-용어-스타일-가이드]]를 따른다.

## 목적
이 문서는 Rulmera OPA Enterprise Knowledge 문서에서 **전문 용어를 원어(알기 쉬운 설명)** 형식으로 통일하기 위한 기준이다.

## 표기 원칙
- 처음 등장하는 용어는 `원어(쉬운 한국어 설명)`으로 쓴다.
- 이후 반복 등장 시에는 문맥에 따라 원어 또는 쉬운 설명 중 하나를 사용한다.
- 관리자/개발자 문서가 아니라면 약어만 단독 사용하지 않는다.

## 권장 표기 예시
- Identity(사용자 신원)
- Authorization(접근 허가)
- Retrieval(지식 검색)
- RAG(Retrieval-Augmented Generation, 검색증강생성)
- Citation(근거 표시)
- Deep Link(원문 바로가기)
- Embedding(의미 벡터화)
- Chunk(지식 조각)
- Ingestion(자료 수집)
- Deployment Fabric(배포 운영 틀)
- On-Prem(사내 자체 운영 환경)
- Tenant(고객 회사 단위)
- Approval Workflow(승인 절차)
- Answer Contract(표준 응답 규격)

## Mermaid 권장 스타일
- 도면은 가능하면 `%%{init: {...}}%%`를 사용해 컬러 가독성을 높인다.
- 사람/사용자 흐름은 파랑 계열
- 승인/정책/절차 흐름은 주황 계열
- 지식/저장/허용된 상태는 초록 계열
- 차단/주의는 빨강 계열
- 배포환경/외곽 구성은 보라 또는 회색 계열

## v0.9 Agentic Execution 필수 용어
다음 용어는 실행형 Worker 문서에서 **처음 등장할 때 최소 한 번 이상 원어 + 쉬운 한국어 뜻을 함께 표기**한다.

- PEP(Policy Enforcement Point, 정책 집행 지점): 정책판정 결과를 실제 실행 차단/허용에 적용하는 지점
- PDP(Policy Decision Point, 정책 판단 지점): 정책규칙을 평가해 허용·거부·승인필요를 결정하는 지점
- Canonical Job(정규 작업 요청): 실행대상과 인자를 확정한 표준 Job
- Job Hash(작업 해시): 승인 후 Job 내용 변경 여부를 확인하는 고정 지문
- Approval Binding(승인 결합): 승인받은 Job Hash와 실제 실행 Job Hash를 묶어 동일성을 강제하는 방식
- Action Preview(실행 미리보기): 사람이 승인할 실제 작업 범위를 Controller가 표시한 내용
- Durable Workflow(내구성 작업흐름): 장애가 나도 상태를 잃지 않고 이어서 실행하는 작업관리 방식
- Workflow(작업흐름): 여러 실행 단계를 순서·분기·조건으로 묶은 전체 절차
- Activity(개별 실행 작업): Workflow 안에서 Worker가 실제 수행하는 한 단계
- Retry(재시도): 일시적 실패 시 정해진 규칙에 따라 다시 실행하는 것
- Timeout(제한시간): 작업이 너무 오래 걸릴 때 중단·실패를 판정하는 시간 기준
- Task Queue(작업 대기열): Worker가 가져갈 실행 작업을 쌓아두는 대기열
- Idempotency(멱등성/중복실행 방지): 같은 요청을 반복해도 의도치 않은 중복효과가 발생하지 않도록 하는 성질
- Fail Closed(판정 불가 시 차단): 권한·승인을 확인할 수 없으면 기본적으로 실행을 허용하지 않는 방식
