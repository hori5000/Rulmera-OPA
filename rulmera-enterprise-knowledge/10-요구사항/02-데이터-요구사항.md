# 데이터 요구사항

## 1. 가장 먼저 필요한 데이터
빠른 검증을 위해 **많은 데이터보다 정답이 분명한 데이터**가 필요하다.

### PoC 최소 세트
| 데이터 | 최소량 | 목적 |
|---|---:|---|
| 대표 기술문서 | 100~300개 | 검색/Chunk/Embedding/출처검증 |
| 최신/구버전 쌍 | 10~20쌍 | 버전 우선순위/충돌경고 |
| 보안등급 L0~L5 문서 | 등급별 10개+ | 권한 누출시험 |
| 장애/해결 사례 | 30건+ | 회사 선임형 답변 검증 |
| 숙련자 Q&A | 30~50건 | 암묵지 후보→승인 Workflow |
| 골든 질문 | 50문항+ | 답변품질 기준선 |
| Allow/Deny 질문 | 100케이스+ | OPA 정책 회귀시험 |

## 2. 실제 고객에게 요청할 자료
- 회사소개/카탈로그(L0)
- 사내 업무절차/SOP/일반매뉴얼(L1)
- 검사방법/생산조건/부서 절차(L2)
- PLC/회로/소스/기술설계(L3)
- Recipe/알고리즘/핵심노하우(L4)
- 고객 NDA/원가/특허 전 자료(L5)
- 장애보고서/유지보수이력/변경이력
- 회의록/설계변경사유/의사결정 기록
- 자주 묻는 질문과 신입 실수 사례
- 사용자/부서/프로젝트/직무/인가 목록

## 4. 파일형식 우선순위
### Phase 1 — 가장 빠른 PoC
Markdown/TXT/PDF(text)/DOCX/PPTX/XLSX/CSV

### Phase 2
스캔 PDF, 이미지, 도면, 소스코드 저장소, 이메일/회의록

### Phase 3
MES/ERP/PLM/SCADA/DB/API 실시간 연계

## 5. 데이터 품질등급
- A: 승인된 최신 정본
- B: 승인됐으나 구버전/유효성 확인 필요
- C: 후보지식/검토중
- D: 출처불명/참고자료
- RAG 기본검색은 A, 필요 시 B까지만 허용한다.
