# 데이터 요구사항 v0.5

> [!summary]
> 이 문서는 제품이 반드시 충족해야 할 기능·비기능 요구를 정리한 요구 기준 문서다.

> [!info]
> 표기 기준: 전문 용어는 가능하면 `원어(알기 쉬운 설명)` 형식을 사용하고, 공통 기준은 [[20-설계/00-용어-스타일-가이드]]를 따른다.

## 1. PoC에 가장 먼저 필요한 데이터
빠른 검증은 **많은 데이터보다 정답·권한·버전이 분명한 데이터**가 중요하다.

| 데이터 | 최소량 | 목적 |
|---|---:|---|
| 대표 기술문서 | 100~300개 | 검색/Chunk/Embedding/출처 |
| 최신/구버전 쌍 | 10~20쌍 | 버전/충돌 |
| L0~L5 문서 | 등급별 10개+ | 권한누출 |
| 장애/해결 사례 | 30건+ | 회사 선임형 답변 |
| 숙련자 Q&A | 30~50건 | 후보→승인 |
| Golden 질문 | 50문항+ | 품질 |
| Allow/Deny | 100케이스+ | OPA 회귀 |
| 신규/변경 파일 세트 | 20건+ | 증분 Ingestion |
| 신규 프로젝트 후보 세트 | 3건+ | Project Candidate |

## 2. 고객 운영 Source
- Windows/NAS 공유폴더
- Git/소스저장소
- 파일업로드
- 향후 SharePoint/DMS/메일/DB Connector

Source는 **수집 지점**이며 권한의 진실이 아니다. 파일 내용과 정책으로 재검증한다.

## 4. 자동분류 후보 Metadata

```yaml

  project: 0.93

```

**자동분류 후보와 승인된 Metadata를 구분**한다.

## 5. 파일형식 우선순위
### Phase 1
Markdown/TXT/PDF(text)/DOCX/PPTX/XLSX/CSV

### Phase 2
스캔 PDF, 이미지, 도면, 소스저장소, 이메일/회의록

### Phase 3
MES/ERP/PLM/SCADA/DB/API 실시간 연계

## 6. 데이터 품질등급
- A: 승인된 최신 정본
- B: 승인됐으나 구버전/유효성 확인 필요
- C: 후보지식/검토중
- D: 출처불명/참고자료

기본 RAG는 A를 우선하고 정책에 따라 B까지 허용한다. C/D는 일반 정답 근거로 사용하지 않는다.

## 7. 변경 이벤트
- CREATE
- UPDATE
- DELETE
- MOVE/RENAME
- PERMISSION_CHANGED
- APPROVAL_CHANGED

모든 이벤트는 `content_hash + source_uri + document_id`로 멱등성을 보장하도록 설계한다.
