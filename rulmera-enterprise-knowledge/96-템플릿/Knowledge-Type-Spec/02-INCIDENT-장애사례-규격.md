# INCIDENT — Incident / Troubleshooting(장애 사례) 규격 v0.7

> [!summary]
> 실제 장애·고장·이상현상에 대해 증상, 영향, 원인, 확인순서, 조치, 재발방지를 구조화한다.

## 필수 항목
- 대상 설비/제품
- 증상
- 영향
- 원인 또는 원인 미확정 표시
- 확인 순서
- 실제 조치
- 결과
- 발생일시 또는 기간
- `project_id`
- `security_level`
- `approval_status`
- 근거 자료

## 선택 항목
- 알람코드
- PLC Tag / Signal
- 로그·그래프·사진
- 교체부품
- 재발방지
- 유사사례 링크

## AI 자동생성 규칙
1. 증상과 원인을 섞지 않는다.
2. 추정 원인은 `원인 후보`로 표시한다.
3. 실제 수행한 조치와 권장 조치를 구분한다.
4. 시간순 로그가 있으면 이벤트 순서를 보존한다.
5. 설비코드는 `M203(송풍기)`처럼 코드와 쉬운 이름을 함께 표시한다.
6. 유사 장애를 발견하면 관련 Knowledge ID 후보를 제안한다.

## 승인 체크
- 원인이 사실 확인됐는가?
- 조치 후 정상화 근거가 있는가?
- 설비/프로젝트 연결이 정확한가?
- 고위험 작업 절차가 포함되면 별도 안전검토가 필요한가?
