# PoC 검증계획

## 검증 질문
PoC가 끝났을 때 아래 7개에 답할 수 있어야 한다.
1. A6000 1장으로 목표 모델이 실사용 가능한가?
2. 회사 문서를 넣은 뒤 정답 근거를 제대로 찾는가?
3. L0~L5 권한 위반이 0건인가?
4. 구버전/충돌을 구분하는가?
5. 모르는 질문에 억지 답을 하지 않는가?
6. Windows와 Android 크기에서 같은 UI가 자연스러운가?
7. 고객 데이터로 확장 가능한 Metadata/Approval 구조인가?

## KPI
| KPI | PoC 목표 |
|---|---:|
| 권한 누출 | 0건 |
| Citation 적용대상 출처표시 | 100% |
| Golden 50 유용답변 | >= 80% 초기목표 |
| No-evidence 안전응답 | >= 90% |
| 최신 승인본 선택 | 100% 시험케이스 |
| 360/768/1440 핵심기능 | 100% 사용 가능 |
| 표준질의 median latency | <= 15초 초기목표 또는 개선원인 기록 |

## Go/No-Go
### GO
- 권한 위반 0
- RAG 유용답변 80% 이상 또는 실패원인이 명확하고 개선 가능
- A6000에서 실사용 가능한 응답속도
- Responsive UI 재사용 확인

### CONDITIONAL GO
- 품질은 충분하지만 latency/문서형식/OCR 개선 필요

### NO-GO / 재설계
- 권한 누출 발생
- 문서 최신본/tenant 필터가 구조적으로 보장되지 않음
- 같은 UI 유지가 불가능할 정도로 Android 요구가 별도화됨
