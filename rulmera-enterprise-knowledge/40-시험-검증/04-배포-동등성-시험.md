# 배포 동등성(Parity) 시험 v0.5

> [!summary]
> 이 문서는 무엇을 어떻게 검증할지와 합격 기준을 정의한 시험 기준 문서다.

> [!info]
> 표기 기준: 전문 용어는 가능하면 `원어(알기 쉬운 설명)` 형식을 사용하고, 공통 기준은 [[20-설계/00-용어-스타일-가이드]]를 따른다.

## 목적

Cloudflare, On-Prem, Customer Cloud에서 **제품 기능이 동일**한지 확인한다.

## 동일 시험셋

| ID | 시나리오 | Cloudflare | On-Prem | Customer Cloud |
|---|---|---|---|---|
| PAR-001 | 로그인/Identity | PASS 대상 | PASS 대상 | PASS 대상 |
| PAR-002 | 텍스트 질의 | PASS 대상 | PASS 대상 | PASS 대상 |
| PAR-003 | 음성→텍스트→질의 | 지원 Profile에서 동일 | 동일 | 동일 |
| PAR-004 | OPA ALLOW/DENY | 동일 | 동일 | 동일 |
| PAR-005 | Citation/Deep Link | 동일 논리 Resource | 동일 | 동일 |
| PAR-006 | Knowledge Inbox | 동일 | 동일 | 동일 |
| PAR-007 | Approval | 동일 | 동일 | 동일 |
| PAR-008 | Continuous Ingestion | Connector별 | 동일 Core | 동일 Core |
| PAR-009 | Audit | 동일 Schema | 동일 | 동일 |
| PAR-010 | UI layout | 동일 Build | 동일 Build | 동일 Build |

## Pass 기준
- Core API Contract 차이 0
- OPA 의사결정 차이 0
- 동일 질문의 Citation resource set 차이가 허용범위 내
- Deep Link 404/권한우회 0
- 환경 때문에 UI Fork가 생기지 않음

## 별도 시험
Cloudflare의 CDN latency와 On-Prem LAN latency는 인프라 특성이 다르므로 **동일 절대성능**을 요구하지 않는다. 기능·보안·계약의 동등성을 본다.
